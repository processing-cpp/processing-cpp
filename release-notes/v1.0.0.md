# CppMode 1.0.0

CppMode 1.0.0 brings a rewritten editor engine, a second renderer, a lot of Java Processing
behavior that was missing or different, and Export Application back for every platform.
Changes since 0.6.1.

## New: the libprocessing renderer (experimental)

Next to OpenGL, sketches can now run on libprocessing, a modern GPU renderer (wgpu, through Bevy).
Pick it with the renderer selector in the editor. OpenGL stays the default.

- 2D and 3D drawing, images, text, input, cursors, blend modes and the shape, rect, ellipse and image modes
- P3D: Processing's camera and perspective, so 3D sketches look the way they do in Java
- Lights that follow Processing's own lighting formula: `lights()`, `ambientLight()`, `directionalLight()`,
  `pointLight()`, `spotLight()`, `lightFalloff()`, `lightSpecular()`, also inside `translate()` and `rotate()`
- Materials: `specular()`, `shininess()`, `emissive()`, `ambient()`
- Outlines stay their stroke color under lights, like Java
- Textures, including lit textured shapes
- PGraphics, custom shaders, `copy()`, reading pixels, clipping, `filter()` on the GPU
- Curves, rounded rects, 3D points and lines, `textureWrap()`, `smooth()`, the depth test, and much
  faster `loadPixels()` / `updatePixels()`
- The libprocessing library ships inside CppMode.zip for Linux, Windows and Apple Silicon Macs, with its
  build cache precompiled, so the first libprocessing run starts quickly. If it can't be found, CppMode
  says so and uses OpenGL instead.

Known gaps: per-vertex fill colors don't blend in P2D/P3D yet (each shape takes one color),
and Intel Macs use OpenGL. Windows and macOS have had less testing than Linux.

## Sketches that now just work

- `selectInput()`, `selectOutput()` and `selectFolder()` work like Java: pass a callback name, keep
  drawing while the dialog is open, and get a `File` in `fileSelected(File selection)`
  (`null` when cancelled). Linux (zenity or kdialog), macOS and Windows.
- `null` is a keyword, so `if (img == null)` compiles as written
- `fullScreen()` sizes the sketch to the display, also from `settings()`, and opens straight into
  fullscreen. `fullScreen(P2D, 2)` picks a monitor and `fullScreen(SPAN)` covers all of them.
- `#FF8800` color literals
- Java static calls: `Math.abs()`, `Integer.MAX_VALUE`, `Float.isNaN()`, `String.format()`,
  `System.out.println()`, `System.currentTimeMillis()`
- `int("42")`, `float("2.5")`, `boolean("true")`, and `int(s)` / `float(s)` on a `String`
- `thread("work")` runs your `work()` in the background
- Sketches with a `static` global build again; 0.6.1 failed to link them and the IDE could run out of
  memory (#15)

## Java behavior

- PShape works like Java's: `fill()`, `stroke()`, `strokeWeight()`, `beginContour()` on shapes,
  `translate()`, `rotate()`, `scale()`, `resetMatrix()`, `getWidth()`, `getHeight()`, `isVisible()`,
  and `setFill()` / `setStroke()` with a color, a `#` literal or `false`
- Groups share the shapes added to them, and transforming a group moves its children, like Java
- `createShape(RECT / ELLIPSE / ARC / TRIANGLE / QUAD / LINE / POINT / BOX / SPHERE, ...)`
- `shape(s, x, y, w, h)` sizes the shape to w by h, and `shapeMode()` works
- PShapes keep their own material under lights, like Java
- `rectMode(CENTER)`, `ellipseMode(CENTER)` and arc modes (`PIE`, `CHORD`) draw like Java with libprocessing
- `fill()` inside `beginShape()`: blended in P2D and P3D, one color per shape or triangle in the default
  renderer, the same as Java
- `screenX()`, `modelX()` and the rest, `frustum()`, `sphereDetail()`
- OBJ models: smooth shading and textures
- The OpenGL renderer now shows `emissive()` and Java's shininess
- `parseInt()` and `parseFloat()` follow Processing's rules: `parseInt("3.7")` is 3, bad input gives 0
  for ints and NaN for floats
- `IntDict`, `FloatDict` and `StringDict` keep insertion order and have the full Java API. `IntList` and
  `FloatList`: `add(index, amount)` adds to a value like Java, `insert()` inserts. `StringList` gained
  `upper()`, `lower()` and `sortReverse()`.
- `split(s, "::")` with a string delimiter, `String.hashCode()`, `min()` / `max()` of arrays,
  `applyMatrix()` with 6 values, `isLooping()`, and the `surface` object (`setTitle()`, `setSize()`,
  `setLocation()`, `setResizable()`)
- `saveJSONObject(json, file)` and `saveTable(table, file)` take Java's argument order (the old order still works)
- `stroke(color, alpha)` and `fill(color, alpha)` work like Java; a colored stroke with alpha used to come out gray
- `PImage` gained `save()` and `blend()`, and `get()`, `copy()` and `resize()` match Java
- `launch()` opens files and links with the default app, and `savePath()` creates folders
- `print()` / `println()` format numbers, colors, booleans and vectors like Java
- `saveFrame()` writes real TIFF files, and the default name matches Java (`screen-####.tif`)

## OpenGL renderer

- Shapes, curves, blend modes, `strokeCap()`, `ellipseMode(CORNER)`, arcs, contours and textures fixed
- PGraphics: pixels, `get()` / `set()`, lights and `tint()` behave like the main canvas

## Export Application is back

- The same Export dialog as Processing's other modes: pick the platforms, the renderer, an app icon
  and where it goes
- Windows: `<Sketch>.exe` with your icon built in. macOS: a `.app`. Linux: an AppImage, with a
  `run.sh` fallback, on x64 and ARM.
- libprocessing exports for every platform that has the library (Linux, Windows, Apple Silicon Macs),
  from any computer, with the library bundled next to the program. Other targets use OpenGL.

## Editor

- A new parser based on tree-sitter: faster and more accurate syntax highlighting, error checking
  while you type, and go to definition
- Clearer compiler errors, with exact line numbers: the Java-syntax rewrites now go through a real
  tokenizer, so strings, comments and directives are never touched

## Faster

- 3D shapes reuse their geometry between frames when they haven't changed
- `box()` and `sphere()` no longer build a new mesh for every size
- Lit shapes in different colors share one material and draw in batches
- Lights are only re-sent to the GPU when they change

## Fixes

- Windows: the compiler finds its own DLLs even with other MinGW installs on PATH (#6)
- Windows: the install wizard no longer wipes your user PATH when it adds MSYS2 (#7)
- Windows: plug-and-play builds compile without errors or warnings
- Wayland: GLEW starts correctly (#9, #14)
- Link errors with the `image()` overloads that were declared but never implemented (#13)
- macOS and Windows: libprocessing uses the right window handles (it assumed X11 everywhere), finds its
  own headers on case-insensitive file systems, and compiles with Apple's libc++
- `prettyVersion` shows correctly in the Contribution Manager (#12)
- `rebuild-jar.py` works on Windows (#8)

## Every release

- CppMode.zip, plus the plug-and-play and CMake packages for using the engine without the IDE
- A test suite runs before every release: translator rewrites, free functions, 39 API areas and 87
  runtime values checked against Java

## Web editor

The web editor at processing-cpp.github.io/editor runs this release. New sketches compile about twice
as fast and download much less, and the compile server updates itself from GitHub releases, tests every
build before it goes live, and rolls back by itself if something breaks. Errors show in the error panel
with a Copy button, and a sketch that fails to start no longer leaves the loading spinner up.
